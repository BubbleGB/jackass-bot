# Task 6 Discord handlers and delivery plan

> Execute inline, TDD, one fresh whole-branch review before push.
Spec: ../../galaxy-neegy-handoff.md Task 6 and user acceptance cases 1–6.
Goal: bind Discord events/commands to existing services; own only acknowledgement,
typing, permitted notifications, bounded output delivery and explicit registration.

- Preserve Task3 actual usage/reservations, Task4 required input/context/access, Task5
  queue/activity/singleton decisions. No live calls/keys/registrations/VPS/deployment.
- Pin discord.js14.28.1 (official registry Node>=18), minimal guild/message/content intents.
  Foundation startup remains validation only; runtime lifecycle activation belongs Task8.
- /ask initial public defer before slow checks, edit public answer. Cooldown/suppressed
  notice fulfils the original with neutral public text, removes that placeholder and sends an ephemeral notice; visibility cannot be
  changed after defer. Staff/help commands defer privately before current access checks.
- Delivery rechecks current channel permissions for every chunk/attempt, parse=[], roles=[],
  explicit participant users max3, replied_user=false. Unpermitted mentions neutralized.
- Long text is rendered as escaped plain text before splitting at Unicode-safe boundaries,
  so split Markdown cannot leave malformed fences/emphasis. Preserve readable answer text.
- Max32 chunks of2000 UTF16 units,3 attempts perchunk, bounded20s delivery; retry only
  definitive retryable non-sends/429 within2s Retry-After. Ambiguous acknowledgement stops;
  never regenerate, replay delivered chunks, or retry unknown acceptance automatically.
- Refresh typing every8s; clear timer on all outcomes. Discord has no stop-typing endpoint;
  failed/silent cases expire server-side after last indicator. No timers generate AI work.
- Registration separate CLI testguild and explicit production/global command. No reconnect
  registration; no registration commands are executed live in this task.
