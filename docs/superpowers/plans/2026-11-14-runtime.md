# Task 8 runtime and production image implementation plan

> Inline execution with TDD and one fresh whole-branch review.

Goal: execute approved handoff Task 8 and the user's five runtime/image acceptance cases.
Architecture: one production Node process composes existing Discord/HTTP/dashboard/services,
PostgreSQL worker lock, lifecycle/health and maintenance. No policy copies in controllers.
Spec: ../../galaxy-neegy-handoff.md A6–A9, Task 8 and current user instructions.

Constraints: exact existing Node/npm and PostgreSQL pins, nonroot image, private database,
Watchtower opt-out, mounted secrets, explicit migrations; no release/registry publication,
production credentials, live APIs, DNS, VPS or deployment. Native CI images must run, not
merely build or emulate. Keep Task 3 accounting and Task 4–7 service decisions intact.

Decisions:
- DB schema verification and singleton acquisition precede gateway login; ingress opens
  only after verified bot identity, actual ready event and successful installed-guild
  reconciliation. A second instance fails closed before login/events. Health readiness
  checks phase, gateway state, DB and ownership; no sensitive diagnostic details.
- Graceful stop gates ingress, disconnects gateway, drains accepted handlers/active queue
  work while retaining lock, then closes HTTP/DB. After 90 seconds cancel through guard;
  allow bounded settlement, force process exit only at the outer 115-second deadline.
- Successful complete bot guild REST listing alone establishes membership/absence.
  Unavailable gateway guilds/outages never prove removal. Fresh joins get disabled defaults.
- Separate accounting retention from configuration deletion: remove cascading guild FKs
  from daily usage/reservations, retaining minimal known usage for 90 days and unresolved
  reservations/uncertain aggregates until reconciliation, even after confirmed removal.
  Late settlement still works without config. Cleanup cannot free unresolved funding.
- Keep Task 7's already approved 12-hour sessions (not historical 7-day proposal). Daily
  cleanup prunes expired auth state/sessions, safe errors7d, audits/known daily90d,
  aggregated completed reservations/receipts7d; retain processing/uncertain metadata.
- Static allowlisted structured logs only; never log raw exceptions, IDs, text, URLs or
  secrets. Compose mounts files, init creates a non-superuser owner of the app DB; no
  automatic migrations. Built assets live in dist/dashboard, backend in dist/web.
- Image smoke uses actual production entrypoint and final image. Read-only mounted test
  preload replaces external SDK login/HTTP only; no test bypass or origin override ships.
  Prove schema-required failure, starting/ready health, single worker, public dashboard/logo,
  event→context→mock provider→ledger→delivery, graceful in-flight stop/restart/no replay.

Review focus: stop during startup; lost lock during ingress/maintenance; partial/failed
membership listings; late over-reservation settlement after removal; secret leakage in
entrypoint/container logs and failed startup. Pin each with unit/PG/image regressions.
